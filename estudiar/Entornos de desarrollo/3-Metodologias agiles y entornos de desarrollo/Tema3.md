# Tema 3: Metodologías Ágiles y Entornos de Desarrollo

## 📌 Resumen Rápido

Las metodologías ágiles son enfoques de desarrollo software que priorizan la **flexibilidad, colaboración y entrega incremental**. Las principales son **Scrum, Kanban, XP y Lean**, cada una con sus propias prácticas y herramientas.

---

## 1. Scrum

### ¿Qué es Scrum?

Metodología ágil basada en **ciclos cortos (sprints)** de 1 a 4 semanas. El equipo entrega un producto parcialmente funcional en cada sprint.

### Los 3 Roles de Scrum

| Rol | Función |
|-----|---------|
| **Product Owner** | Define prioridades y gestiona el Product Backlog |
| **Scrum Master** | Facilita el proceso, elimina obstáculos, protege al equipo |
| **Development Team** | Construye el producto durante el sprint |

### Los 3 Artefactos de Scrum

| Artefacto | Descripción |
|----------|------------|
| **Product Backlog** | Lista priorizada de todas las funcionalidades/demandas del producto |
| **Sprint Backlog** | Tareas específicas del sprint actual |
| **Incremento** | Producto funcional entregado al final del sprint |

### Los 4 Eventos de Scrum

| Evento | Cuándo | Duración |
|--------|--------|---------|
| **Sprint Planning** | Inicio del sprint | 2-4 horas |
| **Daily Scrum** | Cada día | 15 minutos |
| **Sprint Review** | Final del sprint | 1-2 horas |
| **Sprint Retrospective** | Después de la review | 1-1.5 horas |

> **CONSEJO**: Dailies breves = máximo 15 minutos

## 2. Kanban

### ¿Qué es Kanban?

Sistema visual de flujo de trabajo mediante un **tablero con columnas**:
- **Por hacer** (To Do)
- **En progreso** (In Progress)
- **Hecho** (Done)

### Características Principales

- **Visualiza** todas las tareas en un tablero
- **Limita el trabajo en curso (WIP)** - máximo 3 tareas simultáneas
- **Flujo continuo** - no hay sprints fijos

> **CONSEJO**: Usa Trello, Notion o Jira para tableros Kanban

---

## 3. XP (Extreme Programming)

### ¿Qué es XP?

Metodología enfocada en **calidad del código** y colaboración continua.

### Prácticas Principales

| Práctica | Descripción |
|----------|------------|
| **Pair Programming** | Dos programadores en el mismo código (conductor + navegante) |
| **Code Reviews** | Revisión de código entre compañeros |
| **Testing Automatizado** | Pruebas unitarias automáticas |
| **Refactorización** | Mejorar código continuamente |
| **Integración Continua** | Combinar código frecuentemente |

> **CONSEJO**: Practica pair programming al menos una vez por semana

---

## 4. Lean Development

### Origen

Viene del sistema de producción **Toyota** → "Lean Manufacturing"

### Principios

1. **Eliminar desperdicios** - tareas sin valor real
2. **Maximizar el valor** - priorizar lo importante
3. **Mejorar flujo de trabajo** - proceso siempre optimizado
4. **Aprender iterativamente** - feedback constante

> **CONSEJO**: Elimina tareas sin impacto real para aplicar Lean

---

## 5. ScrumBan (Híbrido)

Mezcla de Scrum + Kanban:
- Sprint de Scrum (ciclos definidos)
- Flujo visual de Kanban (tablero)
- Más flexible que Scrum puro

---

## 🧠 Conceptos Clave para Examen

1. **Scrum = sprints + roles + artefactos + eventos**
2. **Roles Scrum**: Product Owner, Scrum Master, Equipo
3. **Artefactos**: Product Backlog, Sprint Backlog, Incremento
4. **Eventos**: Planning, Daily, Review, Retrospective
5. **Kanban = tablero visual + flujo continuo**
6. **XP = pair programming + testing automático**
7. **Lean = eliminar desperdicios + maximizar valor**
8. **Sprint = ciclo corto de 1-4 semanas**

## ✅ Conclusión Fácil de Recordar

1. **Scrum** = estructura con sprints
2. **Kanban** = flujo visual sin sprints
3. **XP** = calidad de código extrema
4. **Lean** = máximo valor, mínimo desperdicio
5. **Se pueden combinar** → ScrumBan es ejemplo
